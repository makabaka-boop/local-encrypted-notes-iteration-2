# 加密便笺工作台（secure-notes-workbench）

纯前端的加密便笺应用：**所有数据只保存在当前浏览器的 IndexedDB 中**，服务器（nginx）仅分发静态文件，不接触任何用户数据。最多管理 **100 条**便笺。

## 安全设计

```
口令（仅内存，绝不落盘）
  └─ PBKDF2-SHA256（随机盐，250 000 次迭代）─▶ KEK（仅内存，不可导出）
        └─ AES-GCM wrap ─▶ 数据密钥 DK（首次创建时随机生成的 AES-GCM-256 密钥）
              └─ 每条便笺：DK + 独立随机 IV(96bit) 的 AES-GCM 加密 ─▶ IndexedDB
```

- **数据密钥封装**：首次创建时生成随机数据密钥，用口令派生的 KEK 经 `wrapKey` 封装后，与 KDF 盐/迭代次数一起存入 IndexedDB 的 `meta` 表。
- **逐条加密**：每条便笺使用全新的随机 IV 做 AES-GCM 加密，GCM 认证标签同时保证机密性与完整性——密文或 IV 被篡改时解密必然失败。
- **明文与口令不持久化**：IndexedDB 里只有密文、IV、修订号、时间戳和封装后的密钥；明文与口令只存在于内存/DOM，锁定即销毁。
- **改口令 = 重新封装（带修订号 CAS）**：修改口令时用新盐派生新 KEK，对同一个数据密钥重新封装，在单个 IndexedDB 事务内「比对封装记录修订号 → 写入」，**便笺密文一个字节都不动**。两个标签页几乎同时改口令时，先提交的一方使另一方的修订号过期，后者事务中止并收到冲突提示，其封装不会落盘——不会出现「双方都报成功、最终只有一方口令有效」。写入中途失败（掉电/配额/异常）时事务回滚，旧封装保持原样，旧口令依然有效。
- **改口令即全员重新认证**：改口令成功后广播 `passphrase-changed`，其它标签页立即销毁内存密钥与明文回到解锁页；发起方本机也一并锁定，需用新口令重新解锁，杜绝落败标签页停留在可编辑状态。
- **会话代际防护（generation）**：解锁、读取、保存、改口令都跨越多个异步等待。会话维护单调递增的代际号，锁定（本地或广播）即 +1；每个异步操作在完成时必须确认代际未变，否则结果作废抛 `LockedError`。`NoteStore` 还在入口、每个 await 边界以及 IndexedDB 事务内**实际写入前一刻**设置检查点——因此「解锁尚未完成就被锁定，迟到结果让明文回到锁定页」「锁定前发起的保存/读取在锁定后落盘或吐出明文」都不可能发生。
- **失败不改旧数据**：错误口令、存储失败（如配额耗尽）都不会改动任何已存记录——所有「检查 + 写入」都在单个 IndexedDB 事务内完成，失败即整体回滚。
- **跨标签页乐观锁**：每条记录带 `revision` 修订号，保存在事务内比对「读取时的修订号」，不一致即中止提交，后写的一方收到冲突提示并被要求**重新载入**，先写的内容不会被覆盖（IndexedDB 事务在同一 origin 内串行，两个标签页同样成立）。
- **锁定即撤明文**：点「锁定」或任一标签页锁定时，通过 `BroadcastChannel` 广播，所有标签页立即销毁内存中的数据密钥、明文缓存与 DOM 中的明文，回到解锁页。
- **加密备份与空库恢复**：
  - **导出仅在已解锁会话中进行**，产出带格式版本（`secure-notes-workbench/backup` v1）的 JSON：只包含密钥封装记录、各便笺密文，以及一份**由数据密钥 AES-GCM 认证加密的清单封套**；不含口令、KEK/DK 原始字节或任何便笺明文（导出不解密任何便笺）。
  - **清单认证整包**：清单采用规范化字节编码（固定字段顺序、长度前缀、便笺按 id 排序）。恢复时先用输入口令解封数据密钥，再打开清单封套并与由文件内容重算的规范化清单逐字节比对——删条、换 id、调换密文、改写修订号/时间戳或替换封装记录都无法伪装成完整备份；随后还会**逐条解密验证每段密文**（明文立即丢弃，不显示）。
  - **恢复只允许目标库为空**：友好预检之外，在**同一个 IndexedDB 事务**内权威确认「封装记录与便笺都不存在」后，才一次性写入元数据与全部便笺。另一标签页抢先初始化/恢复、配额失败、或恢复期间会话被锁定，都会中止事务——已有数据逐项不变，也不会留下「有元数据没便笺」的半个库。
  - 恢复跨越多个 await，受会话代际保护：锁定发生在异步处理中时迟到结果作废，不进入解锁态、不重新显示明文（已原子落盘时只需重新解锁）。
  - 备份恢复后口令不变（仍是封装记录绑定的那个口令）；解锁、改口令、逐条编辑、跨标签修订号规则全部照旧。

## 数据布局（IndexedDB：`secure-notes-workbench`）

| Object Store | 内容 |
| --- | --- |
| `meta` | `wrappedDataKey`：PBKDF2 盐与迭代次数、封装 IV、封装后的数据密钥、封装修订号 `revision`（改口令 CAS 用） |
| `notes` | `{ id, iv, ciphertext, revision, updatedAt }`，上限 100 条 |

## 验收

```bash
docker compose config --quiet
docker compose build
docker compose run --rm verify
```

`verify` 是一次性服务：依次执行 `tsc --noEmit`、`vitest run`、`vite build`，全部通过则以 0 退出。

## 目录结构

```
src/
  crypto.ts    WebCrypto 原语：PBKDF2 派生、密钥封装/解封、AES-GCM 加解密、清单封套
  backup.ts    加密备份：规范化清单、数据密钥认证封套、带版本文件格式与严格解析
  db.ts        IndexedDB 访问层：单事务「检查+写入」（含空库恢复），失败整体回滚
  store.ts     业务层：加解密 + 100 条上限 + 修订号乐观锁
  session.ts   会话：解锁/锁定/改口令/备份导出/空库恢复，锁定广播，内存密钥销毁
  lockbus.ts   BroadcastChannel 锁定广播（含测试用进程内实现）
  ui.ts        纯 DOM 界面：锁定页 / 列表 / 编辑器 / 冲突与篡改提示
  main.ts      入口
tests/         Vitest 测试（fake-indexeddb）
Dockerfile     多阶段：verify（一次性验收）/ app（nginx 静态托管）
docker-compose.yml
```

## 限制与说明

- 口令无法找回：忘记口令即无法解封数据密钥，所有便笺不可恢复。
- 数据绑定当前浏览器与 origin，清站数据即丢失；不提供云同步。更换浏览器时请在已解锁会话中先「导出加密备份」，到新浏览器的空库「从备份恢复」（恢复不覆盖任何已有数据）。
- 上限 100 条便笺，达到后「新建」按钮禁用，服务端（本仓库无服务端）不参与任何数据操作。
